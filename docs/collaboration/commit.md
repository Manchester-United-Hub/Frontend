# 커밋

커밋 메시지 상세 규칙(바디 형식, 예시, 작성 절차)은 [commit-message-generator 스킬](../../.claude/skills/commit-message-generator/SKILL.md)에 있다. 이 문서는 요약과 강제 방식만 다룬다.

## 커밋 단위

- 원자적 커밋: 한 커밋에는 하나의 논리적 변경만 담는다.
- 성격이 다른 변경(예: 문서와 설정, 기능과 리팩터링)이 섞이면 커밋을 나눈다.

## 헤더

```
타입: 간결한 설명 #이슈번호
```

- 영어 소문자, 50자 이내. `#이슈번호`는 선택.
- Husky `commit-msg` 훅이 아래 정규식으로 강제한다. **이 훅이 커밋 규칙의 기준이다.**

```
^(feat|fix|style|refactor|test|chore|init): .+( #[0-9]+)?$
```

## 타입

| 타입 | 용도 |
| --- | --- |
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `style` | 포맷·스타일 (동작 변경 없음) |
| `refactor` | 동작이 같은 구조 개선 |
| `test` | 테스트 추가·수정 |
| `chore` | 설정, 패키지, 문서 |
| `init` | 프로젝트 초기 생성 |

- `docs`, `perf`, `ci`, `build`, `revert`는 훅이 거부한다. 문서 변경은 `chore`.

## 바디

- 한국어로 쓴다. `## 설명`(필수), `## 추가 내용`, `## 변경 내용`, `## 관련 이슈`(선택) 섹션을 쓴다.
