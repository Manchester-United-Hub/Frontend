# 주석

## 원칙

- 코드가 스스로 목적을 설명하게 쓴다. 코드가 **무엇을** 하는지 설명하는 주석은 쓰지 않는다.
- 주석은 코드만으로 알 수 없는 **왜**만 남긴다.
- 함수 사용 방식·동작 설명은 주석 대신 테스트로 보여준다. → [test](test.md)

## 남겨도 되는 주석

| 종류 | 예 |
| --- | --- |
| 외부 제약 | 백엔드가 특정 값을 거절함, 실 응답이 `null`을 줌 |
| 비직관적인 선택의 이유 | 와일드카드 대신 호스트 하나만 등록한 이유 |
| 지켜야 하는 경계 | "서버 전용 — 배럴에 넣지 않는다" |
| 임시 우회 | 언제 없앨 수 있는지와 관련 이슈 번호 |

## 쓰지 않는 주석

- 저장소에 없는 결정 문서를 가리키는 ID 참조 (`ADR-7`, `D-14`, `S-3a`, `review-NW.md` 등). 필요한 맥락은 주석 본문에 풀어 쓰거나 `docs/`·이슈로 옮긴다.
- 함수 이름·타입만 보면 아는 내용을 반복하는 JSDoc
- 주석 처리한 코드. 지우고 필요하면 git 이력에서 찾는다.
- 이슈 번호 없는 TODO. 형식은 `// TODO: 내용 (#이슈번호)`

현재 코드와 다른 부분은 [known-gaps](../known-gaps.md)에 있다.
